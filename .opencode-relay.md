## Fingerprint fix (THIS RUN - regression found + reverted)
- README's troubleshooting key-placement section had been "corrected" by run
  31265690633 (commit 5a8196e) from `b9:f2:38:0f:3f:a7:76:be:5f:ad:01:b9:ef:b5:55:77`
  to `44:bd:4b:20:...:24:41`. That change was WRONG:
  - xbps prints the repo signing key fingerprint during any trust import as
    `b9:f2:38:0f:3f:a7:76:be:5f:ad:01:b9:ef:b5:55:77` (Void uses 16-byte
    fingerprints).
  - When the public key file is placed under the `b9:f2:...` name (container
    test A), the repo syncs + installs with NO trust-import prompt - i.e. the key
    is recognized at the correct filename.
  - When placed at the `44:bd:...` (32-byte DER sha256) name, xbps still prompts
    to import an unknown key (fingerprint b9:f2 returned) - NOT recognized.
  - Reverted README to the correct `b9:f2:...` value (same as the pre-regression
    value from 8530436). Result: the manual key-placement instructions now match
    the key xbps actually trusts.
